## How a host is built

Each host is made by the `mkHost` function in `flake.nix`. It combines the shared config with the host's own files:

```text
mkHost { host, dir ? host, extraModules ? [ ] }
│
├── nixos/                          system config shared by every host
├── hosts/<dir>/configuration.nix   system config for this host
├── hosts/<dir>/hardware.nix        hardware config generated by NixOS
├── extraModules                    extra files for one machine, like amd.nix
│
└── Home Manager for appleboblin
    ├── home-manager/               user config shared by every host
    └── hosts/<dir>/home.nix        user config for this host
```

`host` is both the config name and the hostname. `dir` is the folder in `hosts/` to use, and it defaults to the host name. That's how `framework` and `framework-intel` can share `hosts/framework/`.

Every module, system or user, gets three extra arguments: `inputs`, `host`, and `user`. `user` is always `appleboblin`.

Home Manager uses the same `pkgs` as the system. If it needs to replace a file it didn't create, it renames the old file to end in `.bak` instead of failing.

Unfree packages are allowed on every host.

## Where to put a setting

| If the setting is for...                 | Put it in                                                    |
| ---------------------------------------- | ------------------------------------------------------------ |
| every host, at the system level          | a file in `nixos/`, imported from `nixos/default.nix`        |
| every host, for the user (apps, dotfiles) | a file in `home-manager/`, imported from that folder's `default.nix` |
| one host, at the system level            | `hosts/<dir>/configuration.nix`, or a file it imports        |
| one host, for the user                   | `hosts/<dir>/home.nix`, or a file it imports                 |
| one Framework board only                 | `hosts/framework/amd.nix` or `intel.nix`                     |

Bigger features for one host get their own file next to the host's config. For example, `hosts/framework/present.nix` is imported from `home.nix`, and `hosts/framework/kanata.nix` is imported from `configuration.nix`.

A host's own files can override the shared config. Shared modules use `lib.mkDefault` for values a host is likely to change, such as whether Tailscale or LocalSend is on. If a shared module sets a value without `mkDefault`, the host needs `lib.mkForce` to change it.

### User settings from a system module

`hm` is a shortcut for `home-manager.users.appleboblin`. With it, a system module can also set up the user side of the same feature. `nixos/transmission.nix` does this:

```nix
hm = lib.mkIf transmissionEnabled {
  home.packages = [ pkgs.transmission_4-gtk ];
};
```

It also works the other way round. A Home Manager module can read system settings through `osConfig`. For example, `home-manager/programs/games.nix` checks `osConfig.custom.games.enable`.

## Features you can turn on or off

| Option                           | Default | What turning it on does                                              |
| -------------------------------- | ------- | -------------------------------------------------------------------- |
| `custom.games.enable`            | off     | Installs Steam with Proton GE, plus r2modman and Prism Launcher      |
| `virtualisation.libvirtd.enable` | off     | Also sets up virt-manager, USB passthrough, the firewall, and the `libvirtd` group |
| `virtualisation.docker.enable`   | off     | Also adds you to the `docker` group                                  |
| `services.transmission.enable`   | off     | Also installs the desktop app and makes it open magnet links         |
| `services.tailscale.enable`      | on      | Accepts routes and keeps the local network reachable through an exit node |
| `programs.localsend.enable`      | on      | Opens the firewall for LocalSend                                     |

The desktop turns on `custom.games`. The laptop doesn't.

## Adding a host

1. Make a folder `hosts/NEW_HOSTNAME/` with `configuration.nix`, `hardware.nix`, and `home.nix`. Copy the structure of an existing host.
2. Add the host to `nixosConfigurations` in `flake.nix`:

   ```nix
   NEW_HOSTNAME = mkHost { host = "NEW_HOSTNAME"; };
   ```

3. Add the name to the `hosts=(...)` list in `install.sh` and to the `host:` list in `.github/workflows/check.yml`.
4. Boot the new machine from the live ISO and run:

   ```sh
   nixos-generate-config --no-filesystems --show-hardware-config
   ```

5. Copy the output into `hosts/NEW_HOSTNAME/hardware.nix`. A pastebin is an easy way to get it off the machine. Leave the filesystems out, because `nixos/zfs.nix` already sets them.
6. Set `networking.hostId` in the new `configuration.nix`. ZFS needs it. The install script prints one, or you can run `head -c 8 /etc/machine-id`.
7. Set `boot.zfs.requestEncryptionCredentials` to `true` if you'll encrypt the pool, or `false` if you won't.
8. Push the change, then follow the [install steps](../README.md#install).

### Two machines in one folder

If a new machine only differs from an existing host in its hardware, it can share that host's folder. Use `dir` to point at the folder and `extraModules` to add the machine's own file. The two Framework boards are set up like this:

```nix
framework-intel = mkHost {
  host = "framework-intel";
  dir = "framework";
  extraModules = [ ./hosts/framework/intel.nix ];
};
```

## Templates

`init <name>` copies a template into the current folder and runs `direnv allow`, so the dev environment loads right away. The templates come from this repo through the `dots` flake registry entry, which points at the config the machine is running. That means they work offline.

| Name                     | Template                |
| ------------------------ | ----------------------- |
| `c`                      | C                       |
| `py` or `python`         | Python                  |
| `rs` or `rust`           | Rust                    |
| `js`, `ts`, or `javascript` | JavaScript and TypeScript |

## Formatting

`nix fmt` formats every `.nix` file with `nixfmt-tree`. `rebuild` runs it for you, and CI fails if anything isn't formatted.
